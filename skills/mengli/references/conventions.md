# Project conventions
Read repository instructions, contributing documentation, manifests and CI. Follow local naming, framework and test conventions; do not impose a language or package manager.
Default branches: <type>/<slug> with optional -cu-<ticket>. Default commit: imperative subject, at most 72 characters. Stage explicit paths only. Never stage secrets, build outputs or .claude-work. Ask before every commit. Never merge, approve, close review requests, force push or resolve reviewer threads.
Discover checks from project scripts and CI; record exact commands in the approved plan. Run relevant checks after implementation and fixes. Missing checks are recorded, never invented. Keep task state, logs, QA flows and build cache inside .claude-work. Prefer repository MR/PR templates; otherwise describe the problem, change, tests and evidence.
