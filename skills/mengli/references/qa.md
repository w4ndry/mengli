# Adaptive QA
Select targets from changed areas, not just the repository name. Record commands and requirements in the plan.
Web: use existing browser tests/tooling. Mobile: use project build/install commands, configured app identity and available devices; Maestro is optional. Desktop: use existing application automation and tests. Backend/CLI/library: use executable tests, requests or commands with explicit assertions.
Keep reusable automation and build cache under <repo>/.claude-work/shared/<target>/; task evidence under <workdir>/qa/attempt-N/. Never reuse another project's flows. Build reuse requires unchanged source and configuration.
Each AC gets PASS only with an assertion and recorded evidence. Distinguish product FAIL from ENV_BLOCKED and UNVERIFIED. Retry product fixes up to maxAttempts and navigation repairs up to maxHeals without weakening assertions. Missing credentials or tools block verification; never guess credentials. Record screenshots/video when available and relevant; otherwise retain logs and test reports. Video absence never prevents writing mini-review.md. Report all limits honestly.
